# Product & Analysis Skill Pack

## Global Principles
- Always separate facts from assumptions
- Always highlight open questions explicitly
- Prefer structured Markdown outputs
- Never invent data, metrics, or constraints
- Use enterprise-grade language (no casual tone)

## Artifact Standards

### PRD
Sections required:
- Problem statement
- Business goals & success metrics
- In-scope / out-of-scope
- Personas
- User flows
- Functional requirements
- Data requirements
- Non-functional requirements
- Risks & dependencies
- Rollout considerations
- Open questions

### User Stories
- INVEST-compliant
- Vertical slices only
- Explicit dependencies
- Include edge cases

### Acceptance Criteria
- Given / When / Then
- Negative and boundary cases mandatory
- Permissions, roles, and data states included

### NFRs
Must include:
- Performance
- Security
- Privacy
- Reliability
- Observability
- Accessibility
- Compliance (where applicable)

### Governance
- Decisions recorded as ADR-style notes
- Risks scored (Low / Medium / High)
- Assumptions tracked separately
