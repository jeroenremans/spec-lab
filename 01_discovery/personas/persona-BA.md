# Persona — Business Analyst (BA)

**Name:** Sarah (composite)  
**Role:** Business Analyst at we+  
**Experience:** 3–7 years BA experience; proficient with Confluence, Jira, Excel; new to Claude Code

---

## Goals
- Draft and refine specs quickly without losing context between sessions
- Get PRD v1 from raw intake to stakeholder review in under 90 minutes
- Ensure no requirement is left vague or assumption unlabelled
- Track which sections still need review without opening every file

## Daily frustrations
- Specs live in email threads, Confluence pages, and chat messages — no single source of truth
- Stakeholder feedback arrives as comments scattered across formats (email, Word, Confluence inline)
- Writing AC for every story takes disproportionate time vs. business value added
- After a project pause, re-reading specs to find "where were we?" wastes significant time

## How they use the workbench
- Opens the app at the start of each work session
- Browses the "To Review" sidebar section to find what needs attention
- Uses Claude Code slash commands (`/intake-to-prd`, `/epics-to-stories`) to generate draft artifacts
- Edits and tags sections in the viewer for follow-up
- Saves → commits → shares the repo link with the PM for review

## Comfort with tech
- Comfortable with browser-based tools, markdown basics
- Needs clear error messages — will not debug Python or Node.js issues independently
- Expects setup to take < 5 minutes

## Success for this persona
"I ran `/intake-to-prd` this morning and had a PRD v1 ready for the PM by lunch — with all assumptions explicitly labelled."

## Theme preference (theme-switcher context)
- Preferred themes: Warm Paper (solo deep work), Teal Corporate (team reviews)
- Sets preference once per device; persistence is critical
- Extended sessions (4–6h/day) make readability and low eye-strain the top priority
