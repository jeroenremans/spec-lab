# Persona — Product Manager (PM)

**Name:** Tom (composite)  
**Role:** Product Manager at we+  
**Experience:** 5+ years PM; works across multiple client streams simultaneously; heavy Jira/Confluence user

---

## Goals
- Know the maturity of each spec set without diving into every file
- Approve PRDs and user stories before stories move to AC generation
- Track architectural decisions and risks in one place
- Ensure specs are ready for handoff to delivery team with no ambiguity

## Daily frustrations
- No single view of "what phase is this project in?" across multiple streams
- Decision rationale is lost over time — why did we choose X over Y?
- Risk register is usually a forgotten Excel sheet, not linked to actual requirements
- Spec quality varies widely depending on which BA wrote it

## How they use the workbench
- Reviews PRDs in the app using the viewer (read-only consumer mostly)
- Adds `[REVIEW]` and `[CLARIFY]` tags on sections needing rework
- Checks the `04_governance/` folder for decision records and risk log before sprint planning
- Occasionally runs `/risk-log-update` or `/decision-record` after key stakeholder sessions

## Comfort with tech
- Browser-savvy; comfortable with markdown reading
- Will not run CLI commands independently; relies on the BA to run slash commands
- Needs the governance artifacts to be printable / shareable (markdown renders to clean output)

## Success for this persona
"I opened the risk log before the sprint planning meeting and could instantly see the top 3 risks with mitigations — no hunting through emails."

## Theme preference (theme-switcher context)
- Preferred themes: Bold Agency (client demos, screen shares), Teal Corporate (daily reviews)
- Needs to switch themes quickly before a screen share — speed of switch matters
- Discoverable switcher in topnav is critical (will not dig through settings)
